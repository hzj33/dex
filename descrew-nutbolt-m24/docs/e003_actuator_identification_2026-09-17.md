# E003真机执行器辨识与部署侧匹配对照，2026-09-17

结论：从既有6条真机日志离线辨识出DexH13位置模式的高置信一阶执行器响应（R²≥0.92，i3被动除外），无需新真机数据。辨识出的真机执行器模型单独驱动学生估计闭环即复现真机"无重抓/松开推迟"卡住签名——执行响应形态本身是充分原因。指令低通塑形三档全部恶化为纯旋拧，**部署侧滤波修复被证据否定**；有证据支持的修正路线是用辨识参数作区间的执行器随机化蒸馏。

## 用户问题与SDK事实

用户问"PD响应参数如何确认"。SDK手册3.5.1：位置模式是**梯形速度规划的点到点运动**（最大速度/加速度为协议参数），不是PD伺服；SDK有`setMotorMaxSpeed`（设置）无速度查询接口。因此经典PD增益不存在可读值，可确认的是黑盒输入-输出响应模型（增益/时间常数/延迟/限速），途径：(1)日志辨识（本文，已完成）；(2)真机阶梯测试细化（可选协议见文末）；(3)`setMotorMaxSpeed`把限速钉到已知值消除固件默认不确定性。

方法依据：FOPDT辨识为标准方案（[经典FOPDT阶跃辨识](https://pub.towardsai.net/classic-methods-for-identification-of-first-order-plus-dead-time-fopdt-systems-d81b0484aa4a)、[MATLAB SIT夹爪辨识](https://www.researchgate.net/publication/318539548_Model_Identification_of_a_3_Finger_Adaptive_Robot_Gripper_by_Using_MATLAB_SIT)、[MIT欠驱动机器人系统辨识](http://underactuated.mit.edu/sysid.html)）；数据驱动执行器建模见ANYmal执行器网络（[Hwangbo 2019](https://arxiv.org/abs/1901.08652)）与其无监督扩展（[UAN](https://arxiv.org/html/2502.10894v1)）。[Actuator Reality Shaping](https://arxiv.org/html/2607.02205v1)走"改硬件内环复现仿真动力学"路线，需要可编程内环，DexH13黑盒位置模式不适用，仅验证响应匹配方向价值。

## 混合重放对照（估计器级，无接触物理）

策略目标驱动辨识执行器模型，模型输出回填为测量关节：

| 条件 | 阶段计数 | 首次松开步 |
|---|---|---|
| 真机执行器模型反馈 | 110/32/58/0 | 87 |
| 真机+目标低通τ=0.05/0.1/0.2 | 均为200/0/0/0 | 无 |
| 参考签名：真机日志 | 86/23/107/0 | 78 |
| 参考签名：仿真闭环（卡死组） | 76/51/30/43 | 16 |

真机执行器模型单独进环即得"无重抓、松开推迟2.7-5.4倍"签名；低通塑形加重滞后使签名更差（纯旋拧坍缩），**因为真机缺的不是滞后而是训练分布中的接触交互形态**。用户假说"真机关节角度未达到松开触发条件"被定量支持：松开触发依赖的关节响应形态证据在真机执行形态下于第87步才首次勉强出现且永不完整。

## 局限

- 20Hz采样、0.05rad平滑增量：延迟只能分辨50ms整数倍，加速度不可分离；vmax由饱和拟合间接估计。
- 混合重放无接触物理，是估计器级充分性证据，不是完整闭环物理复现。
- 6条日志均来自同一次装夹批次；不同负载（接触中）响应可能更慢，日志辨识偏空载/轻载侧。

## 修正路线建议（待用户授权）

1. **执行器随机化蒸馏**（有证据支持）：在蒸馏环境中把学生侧执行从PD合同换为/混入一阶执行器模型，参数在辨识区间内随机（a∈[0.2,1.0]、延迟∈{0,1}步、vmax∈[0.5,1.2]、i3按耦合曲线被动），验收=新学生在真机日志流反事实重放中恢复周期签名（含重抓）+原仿真五轮不退化。教师仍冻结，属学生蒸馏目标变更。
2. 可选补充辨识协议（真机1-2分钟，用户执行）：空载、每关节依次发±0.1rad阶梯目标各10次，用SDK最高频率轮询`getJointPositionsRadian`记录，同脚本辨识可分离延迟/加速度/限速；或先`setMotorMaxSpeed`钉已知值再测。
